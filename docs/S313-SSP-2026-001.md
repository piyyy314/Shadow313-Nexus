## System overview

Shadow313 NEXUS is a cybersecurity engineering toolkit and lab platform. The repository contains Python packages, CLI tooling, APIs, SOC-oriented components, static dashboards, detection content, local containers, and experimental security integrations.

The repository does not establish that all components are deployed, connected to live telemetry, or operated as a production security service.

### Hosting and system boundary

- GitHub hosts source control, code review, and CI workflows.
- Vercel hosts the public static website and API gateway.
- Cloudflare manages DNS for shadow313.com; Vercel remains the DNS/hosting provider for shadow313.dev.
- Hetzner is the planned backend host. Backend provisioning, hardening, deployment, and production validation have not been established by this worksheet.
- Local Docker/PostgreSQL services are development and test environments unless separately deployed and evidenced.
- Optional AI, threat-intelligence, storage, and notification integrations may transmit data according to their runtime configuration. No blanket “data never leaves the system” guarantee is made here.

## Cryptographic and evidence limitations

- A hash-chain value is not a digital signature.
- A custom timestamp marker is not a trusted timestamp authority or proof of time.
- HMAC is not publicly verifiable without the relevant secret key.
- Experimental PQC code is not equivalent to a FIPS-validated cryptographic module.
- A generated report, receipt, or control mapping is not independent audit evidence unless its provenance, signer identity, key custody, and verification process are established.

The Aegis PQC and receipt demonstrations must label simulated, locally authenticated, and publicly verifiable states distinctly.

## Evidence required before a control can be marked implemented

1. A named production environment and current deployment record.
2. A verified system/network diagram and data-flow inventory.
3. Identity, authorization, and secrets-management configuration.
4. Current asset and dependency inventory, including an SBOM.
5. Completed vulnerability scans with findings, exceptions, and remediation records.
6. Production audit-log samples, retention, access, and integrity evidence.
7. Backup configuration and a successful restore exercise.
8. Key-management and cryptographic validation evidence.
9. Incident response procedures and exercise results.
10. Independent assessment evidence where a framework or certification claim is made.
